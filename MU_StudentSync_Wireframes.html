1 — Register

  • Labelled fields Visible labels stay above each field at all times, not placeholder-only — readable at 200% text scale without disappearing.
  • Useful errors Inline error text sits directly under its field, not in a blocking dialog, so the user can keep typing.
  • Touch targets Every field and the Register button are ≥48dp tall.
  • Preserve input Typed values and shown errors survive screen rotation (state restored in onSaveInstanceState).
  • Back navigation System Back returns to the previous screen predictably; no custom back-trap.

3 — Student Profile / My Group

  • Ownership protection Student number is read-only here — matches the brief's rule that only a lecturer can correct it.
  • Sync status A persistent status chip (Saved locally / Pending / Syncing / Synced / Action required) tells the user what state their data is in at a glance.
  • Flexible layout Scrollable column so content reflows correctly at large text sizes instead of clipping.
  • State survival Group-change request state (Pending) persists across rotation and app restart via Room, not just in-memory.

5 — Student Editor (Lecturer)

  • Capacity rule A full group (15/15) is visibly flagged and disables Save for that group — prevents overfilling at the UI layer (server remains the source of truth).
  • Permission boundary Student number is editable here specifically because only a lecturer reaches this screen — contrasts directly with Screen 3 where it's locked.
  • Predictable Back Cancel and system Back both discard changes without saving, consistently.

Note: these wireframes are intentionally low-fidelity (box-and-label) to support fast iteration and peer review before/alongside implementation, per the lab's Activity A requirement.
